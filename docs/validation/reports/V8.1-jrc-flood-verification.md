## Result

crc-sdk's local copies of JRC's files are bit for bit JRC's. Its curves are the least-squares
Gumbel curves the statement describes, with one exception: about 3 pixels in 10,000 that should be
fitted are not, because crc-framework's optimizer gives up on them. Separately from fidelity, a
large share of flooded pixels gets no curve by rule, and the curves depart from the published
depths at short return periods.

## Found on the way (this machine and this repository, not crc-sdk)

- **rasterio.** Version 1.5.2 has no package for macOS 14, so uv had compiled it against Homebrew's
  GDAL. Two faults followed: Homebrew's libheif asked for a libx265 that was gone (repaired with
  `brew reinstall libheif`, as you chose), and Homebrew's GDAL brings its own Arrow, which breaks
  pyarrow in the same process (older tests of this repository failed once rasterio was loaded).
  `pyproject.toml` now holds rasterio below 1.5.2 on macOS, where 1.5.1 is self-contained; the
  Homebrew repair is no longer what the project relies on. Docker was not needed.
- **Scripts from standard input.** crc-sdk validates a large table in a worker process; a script
  piped to `python -` cannot be re-imported by it and the run ends with `BrokenProcessPool` after
  the fit (1,689 s lost once). Run through a module or a file.
- **The publisher's server** timed out once on a headers request; the reference reader now tries
  again after a pause.

## Departures from the plan

- The reference reader uses numpy (the plan said `struct` and `zlib`; decoding does use only
  those, the arrays are numpy). It imports neither crc-sdk nor rasterio.
- The out-of-coverage request was run with a cache only; the stream-mode error is read in the code.
- Candidate findings were entered after the run with their evidence, not before it as "code reading".
- The tolerance for curve parameters was set to 1e-6 m before the final run without first reading
  the optimizer's objective in crc-framework-rs.
- A network-off run of cache reuse was not made; the cache probe covers `offline` mode instead.

## Limits

- Five GloFAS tiles of 271, one EFAS box. A `confirmed` outcome covers those, the curated policy,
  all return periods and a cache.
- Verification says nothing about whether JRC's depths are right; Stage 3 compares them with FEMA
  zones, gauges and Harvey high-water marks.
- The caches hold 4.2 GB under `data/cache/validation/jrc-flood/` (git-ignored).
